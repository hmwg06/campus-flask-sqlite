# Campus implementation plan

**Goal:** Implement a Vietnamese Flask + SQLite application covering M03, M04, M10, M17, M20.
**Architecture:** App factory, SQLite with foreign keys, server-rendered Jinja pages, declarative validated CRUD, explicit workflow endpoints. Keep app.py as the runnable entry point.
**Tech Stack:** Existing Flask, Python standard sqlite3, Werkzeug passwords, local CSS/JS.
**Authorization:** User requested immediate implementation using SQLite; execute inline.

## Design and constraints
- Four roles: admin, staff, teacher, student. Staff owns official records; teachers access assigned classes; students see their own records and published course content.
- M03 student identity and study status history; M04 programs, curriculum versions, subjects, classes, enrollments and official published results.
- M10 shared resources linked to subjects, source/version/license metadata, upload/download authorization, reviewed questions with four choices. No fake AI or SSO integration.
- M17 aggregate counts and source-labelled CSV reporting; no invented HEDI/KPI definitions.
- M20 local accounts, password changes, role changes/deactivation, audit history; prevent removal of final active admin.
- SQLite persistence, CSRF protection, hashed passwords, parameterized SQL, bounded input, explicit sample data command.

## Verification
Use unittest and Flask test client against temporary SQLite files. Verify each module renders, unauthorized mutations fail, grade/resource visibility respects publication and class enrollment, uploads cannot bypass checks, records survive reopening. Smoke check actual local HTTP server if possible.

## Review focus
Duplicate codes and relationships must yield useful validation errors; inactive accounts lose access immediately; self/last-admin lockout prevented; unpublished content and other students' records stay private; CSV cells cannot execute spreadsheet formulas.

## Execution evidence
- Initial unittest run failed on missing create_app, as expected before implementation.
- Fourteen integration tests pass with temporary SQLite databases, including reopening a database, setup, all form renders, upload restrictions and cross-role access.
- Independent review identified inactive relation loss and access after teaching reassignment. Added two regression tests, observed both fail, then fixed both and ran all fourteen successfully.
- Desktop dashboard (1440px) and compact viewport (headless Edge minimum width 500px) visually inspected using isolated browser profile and temporary sample data. Learning page also rendered for inspection. No user database seeded or reset.
- Ruling: implement the documented core workflows of the five modules; SSO/AI, official KPI definitions and integrations without supplied service/configuration remain explicitly unconfigured. See README for full scope.
